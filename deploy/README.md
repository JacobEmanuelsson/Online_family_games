Build the client with `npm ci` and `npm run build`. On the host set `NODE_ENV=production` and `PUBLIC_ORIGIN=https://your-domain.example` for the backend, then run the installed `tsx server/start.ts`. Keep port 3000 on loopback. Run Caddy on the same host with the supplied Caddyfile, a bare hostname in YATZY_DOMAIN and the absolute dist directory in YATZY_DIST. DNS and certificate issuance must work before inviting players. Allow public HTTP and HTTPS only for the web service. This configuration assumes Caddy receives connections directly from players. Behind a CDN, configure its verified client IP handling and restrict origin access before relying on per-IP limits.

The in-process limits suit one server. They reset on restart and users sharing an IP share the room-attempt limits. Large distributed floods need upstream DDoS protection from the host or CDN.

For pre-merge review, invoke the Yatzy security reviewer on the proposed diff with GitHub Copilot where supported. The separate security-checks workflow runs automatically on pull requests into main. Require pull requests and the security-checks status check in the main branch ruleset, including for administrators if appropriate. Running the workflow alone does not block direct pushes.
